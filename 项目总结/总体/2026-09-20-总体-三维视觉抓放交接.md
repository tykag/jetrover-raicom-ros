# 2026-09-20 三维视觉抓放交接

> 功能：RGB-D 三维视觉定位、自动抓取、自动堆叠放置  
> 平台：ROS1 Melodic、JetRover、原装深度相机  
> 当前状态：代码已完成第一版，本地语法检查通过；实车标定和联调未完成。

## 1. 目标

方块约 5 cm，夹爪开口约 5.5 cm，纯固定姿态示教误差较大。因此改为：

```text
YOLO 识别目标
→ RGB-D 计算目标三维坐标
→ 相机坐标转换到机械臂坐标
→ 受限逆运动学计算抓取姿态
→ 机械臂自动抓取
→ 导航到园区
→ 自动选择低层/高层并松爪
```

不采用完整 MoveIt；当前仍使用现有总线舵机接口和受限逆运动学。

## 2. 已修改文件

### `tools/04_vision_car/raicom_arm.py`

- 从 `/depth_cam/depth/camera_info` 动态读取相机内参，不再只使用硬编码参数。
- 从目标框附近 ROI 读取深度，不依赖方块中心单个像素。
- 过滤 0、无效、超范围深度。
- 对 ROI 深度使用中位数和离散度检查，处理反光/深度空洞。
- 增加连续多帧三维坐标稳定检查。
- 增加 `measure_from_view()`：只计算坐标，不移动机械臂。
- 增加 `measure_stable_from_view()`：连续采样并判断坐标稳定。
- `grasp_from_view()` 使用三维坐标和逆运动学计算：
  `approach → goal → close → lift`。
- `Arm.place(height, park=None)` 支持低层/高层和园区专用放置姿态。

### `tools/04_vision_car/raicom_auto.py`

- 增加服务：

  ```text
  /raicom/measure_grasp
  ```

  只识别并输出三维坐标，不移动机械臂。

- 增加参数：

  ```text
  ~grasp_mode:=fixed
  ~grasp_mode:=3d
  ~stack_capacity:=2
  ~place_settle_sec:=0.6
  ```

- `fixed` 为旧的视觉对位+固定姿态抓取；
- `3d` 为三维坐标+逆运动学抓取；
- 默认仍为 `fixed`，未完成实车标定前不要启用 `3d`；
- 每轮只抓一个、放一个；
- 每个园区默认两摞、每摞两层：

  ```text
  第1块：park1/park2 第一摞低层
  第2块：park1/park2 第一摞高层
  第3块：park1_b/park2_b 第二摞低层
  第4块：park1_b/park2_b 第二摞高层
  ```

- 每个园区默认最多 4 块；超过容量会停止；
- 导航到放置点后发布底盘停止，并等待默认 0.6 秒再放置。

## 4. 实车验证顺序

### 第一步：只验证三维坐标，不动机械臂

启动导航、YOLO 和 `raicom_auto.py` 后执行：

```bash
rosservice call /raicom/measure_grasp
```

预期输出类似：

```text
success: True
message: "xyz=(0.238, -0.041, 0.126)m depth=0.421m valid=... spread=...m"
```

若出现 `no valid depth`，先处理深度话题、深度编码、RGB/深度对齐或目标表面反光问题，不得直接让机械臂动作。

### 第二步：验证手眼坐标

记录程序输出的：

```text
xyz
depth
valid
spread
```

用尺子测量相机到方块的实际距离，并确认机械臂坐标的前后、左右、上下方向正确。

当前代码仍使用已有手眼矩阵和机械臂模型参数，必须实车验证，不能仅凭代码认为准确。

### 第三步：空动作测试

目标坐标确认后再执行：

```bash
rosservice call /raicom/test_grasp
```

第一次测试时方块旁边保持空旷，手放在急停/断电位置，机械臂低速观察：

```text
look_cargo
→ 预抓取位置
→ 目标位置
→ 闭合夹爪
→ 抬升
```

出现方向错误、超范围或碰撞趋势，立即执行：

```bash
rosservice call /raicom/abort
```

### 第四步：启用完整三维抓取

只有前面测试通过后，才启动：

```bash
python3 ~/yolo_models/raicom_auto.py _grasp_mode:=3d
```

完整流程仍然是：

```text
回抓取区 → 抓一个
→ 去对应园区
→ 底盘停止并等待
→ 放一个
→ 再回抓取区抓下一个
```

## 5. 自动放置与堆叠

比赛台面高度约 15 cm，方块约 5 cm。放置逻辑不是连续拿两个，而是每轮重新抓取：

```text
第1轮：抓1 → 第一摞低层
第2轮：抓2 → 第一摞高层
第3轮：抓3 → 第二摞低层
第4轮：抓4 → 第二摞高层
```

仍需在实车上标定：

```text
place_down_low
place_down_high
```

它们分别代表第一层和第二层的机械臂放置姿态。台面高度不能直接换算成舵机脉冲，必须结合机械臂基座高度、夹爪长度和实际方块高度调整。

如果一个园区要放 4 块，路点文件必须有：

```yaml
park1:
park1_b:
park2:
park2_b:
```

`park1_b`/`park2_b` 是第二摞的底盘停车点，不是自动生成的坐标，必须现场示教并保存。

## 6. 底盘速度要求

底盘不能在抓取或放置时持续移动：

```text
导航阶段：正常速度
进入工作区：减速
抓取/放置：完全停止
等待 0.6～1.0 秒
机械臂动作
```

夹爪只有约 5.5 cm，方块约 5 cm，横向余量很小。底盘运动会造成横向漂移和机械臂振动，必须先停底盘再抓放。

## 8. 急停与回退

急停：

```bash
rosservice call /raicom/abort
```

如果三维抓取未标定成功，先回退到默认固定姿态模式：

```bash
python3 ~/yolo_models/raicom_auto.py
```

不要在手眼矩阵、坐标方向或逆解未验证前使用：

```bash
python3 ~/yolo_models/raicom_auto.py _grasp_mode:=3d
```
