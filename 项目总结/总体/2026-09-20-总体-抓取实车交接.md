> 功能：停在台前抓一块方块  
> 平台：ROS1 Melodic、JetRover 麦克纳姆、大白双目  
> 上一份方案：`2026-09-20-总体-三维视觉抓放交接.md`（代码设计；实车没有走通）  
> 当前结论：不要自动导航，不要用三维逆解抓取。只用手柄对正后的固定姿势。

## 2. 为什么三维抓取没做成

方块约 5 cm，夹爪张开约 5.5 cm，左右只剩约 2.5 mm。下面每一项的误差都是厘米级，叠在一起必夹空。

- 程序用的 `/depth_cam/rgb/image_raw` 是**左镜头**，不是夹爪正前方。画面居中时，夹爪还在方块右边，还要再往左才正对。
- 贴纸中心深度经常是 0。旁边的有效点有时是地面，距离会从约 25 cm 跳到 33 cm、61 cm。
- 厂方手眼矩阵没有在这台车上对过，左右前后不能当准。
- 逆解会从侧面够。侧向偏差曾到 9.7 cm，大于夹爪开口。
- RViz 2D Pose Estimate 之后记下的地图点，和车的真实位置差了约 53 cm、37 度。导航去这个点时规划失败，恢复动作把车推进台子。

## 3. 夹爪和最后一组手臂

舵机 ID 10。用户标定：

```text
180  更开（最后一次要求停在这里）
200  张开
350  闭合
```

脉冲变了不代表爪子一定动了。10 号舵机曾回报误差 0，但爪子外观没动。以眼睛为准。

冲台之前，最后一次手调是：

```text
joint1  500
joint2  280
joint3  237
joint4  640
joint5  500
夹爪    先 180，再 350
```

`raicom_grasp_spot.yaml` 里的手臂仍是更早的 `2:269`、`4:604`、夹爪 `200`，没有改成上面这组。文件里的 AMCL 点**禁止再导航**。

开导航会把臂带回开机姿势，大约 `2:667  3:42  4:208`，夹爪 500。

## 4. 现在怎么抓

1. 手柄把车摆到夹爪正对方块的正面，不要斜着对棱角。
2. 手臂用第 3 节那组脉冲，夹爪先 180。
3. 确认正对后，夹爪收到 350。
4. 不要 `move_base` 去 `raicom_grasp_spot.yaml` 的 `amcl`。
5. 不要 `_grasp_mode:=3d`，不要 `rosservice call /raicom/test_grasp`（它会先去 `look_cargo`，那个角度深度整幅变成 0）。

物块只歪了一点：手臂姿势不变，底盘只横移几厘米，把物块对回左画面里「夹爪正对」的位置，不是画面对中。对不上就放弃这一块。

第二层倒了：不要用高层姿势。贴纸还在高层高度就抓高层；只剩一层就用低层。倒在旁边、已经不在夹爪正前方的，这一轮不抓。

## 5. 手柄

抓取脚本会 `rosnode kill /joystick_control`。导航启动参数是 `use_joy:=false`，不会带手柄。

不能控时：

```bash
roslaunch hiwonder_peripherals joystick_control.launch
```

先取消导航目标，再停底盘：

```text
move_base cancel_all_goals
/hiwonder_controller/cmd_vel  全 0
```

看左镜头：

```bash
export DISPLAY=:0
rosrun image_view image_view image:=/depth_cam/rgb/image_raw
```

窗口在小车屏幕上。
