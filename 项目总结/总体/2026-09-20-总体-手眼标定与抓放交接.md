## 1. 推翻上一份文档的两条结论

上一份说「`look_cargo` 那个角度深度整幅变成 0」「贴纸中心深度经常是 0」。实测不成立：

```text
look_cargo 姿势，连续 5 帧

  中心 ROI 有效 957~961 点，中位深度 0.224 m，5 帧完全一致

  xyz=(0.338, 0.010, 0.091)  depth=0.220  valid=841  spread=0.004
  grasp_from_view 可达性检查 True
```

顺带排除了 LDP（激光散斑投射器 `/depth_cam/set_ldp`）。厂方示例全部 `set_ldp(False)`，本以为是深度空洞的原因，实测开关只差 0.5 个百分点：

```text
LDP OFF  有效 57.8%     LDP ON  有效 58.3%
```

**深度、内参、五帧一致性、逆解全都正常。`grasp_from_view` 实跑返回 True，逆解有解
（pitch=0，approach=[508,128,88,896,500]，goal=[507,126,193,789,500]），
但夹爪没对准方块。** 偏差来自 `_HAND2CAM` 的平移。

## 2. 为什么只需要标平移

`raicom_arm.py` 里的手眼矩阵：

```text
[ 0  0  1  -0.101]
[-1  0  0   0.011]
[ 0 -1  0   0.045]
```

旋转部分全是 0/±1，是相机安装朝向决定的纯轴向置换（90° 整数倍），装配公差影响不到。
平移三个数是厂方标称值，每台车的相机实际位置差几毫米到几厘米，这才是夹不准的原因。

**真值不用 ArUco 板。** `pick_down` 是手柄调出来、已验证能夹住方块的姿势，对它的关节做
正解，得到的就是「夹爪成功夹住方块时所在的位置」= 方块真实中心。这样标出来比教科书
手眼标定更适合抓取：正解末端到夹爪钳口之间那段未知偏移会被一起吸收，因为逆解瞄的也是
同一个末端坐标系。

数学上（`_block_in_arm` 的管线）：

```text
P_top = R_fk · (R_h2c · cam + t_h2c) + t_fk
误差   Δ_base = P_true - P_measured = R_fk · Δt_h2c
修正   Δt_h2c = R_fkᵀ · Δ_base          # R_fk 取测量姿势（look_cargo）的正解旋转
```

## 4. 代码改动

### raicom_arm.py

- `_HAND2CAM` 常量 → `_HAND2CAM_FACTORY` + `load_hand2cam()`，平移从
  `~/yolo_models/raicom_handeye.yaml` 读，文件不存在退回厂方值。按 mtime 缓存
  （`_block_in_arm` 一次测量调 5 次，不能每帧读盘）。
- `Arm.place()` 重写。原来 `self.go(down)` 把 yaml 里 `place_down_*` 的夹爪值一起发出去，
  那个值之前是 250（半开），移动途中方块就掉了。现在移动阶段强制用 `pick_close` 的 350，
  不看 yaml 那一项；到位才松；松完先垂直抬到 `pick_hover` 再回前视（原来直接扫回
  `look_front`，夹爪贴着刚放下的方块横扫容易碰倒）。
- `DEFAULT_POSES["look_front"]` 同步改成初始姿势。

### raicom_grab_manual.py

新增 `align`（YOLO 视觉对位）、`ready_low` / `close_low`（低层）、
`place_low` / `place_high`（放置，夹紧移动最后才松）、`save_low`（记低层姿势）。

两处改动是修隐患，不是加功能：

- `open` 原来是 `arm.go("pick_down")`，低层抓完调它会把臂拉回高层关节再松手，方块掉在
  错的地方。改成 `read_current_joints()` 后只改夹爪，关节不动。
- `close` 原来直接 `arm.go("pick_close")`，高层关节写死在那个姿势里。以后重调 `pick_down`
  忘了同步 `pick_close`，闭合前臂会先跳回旧位置。改成「取对应层 down 的关节 +
  `pick_close` 的夹爪值」，和 `Arm.pick()` 一致。

### raicom_handeye.py（新）

```bash
python3 raicom_handeye.py show     # 当前矩阵 + 相对厂方值的偏移
python3 raicom_handeye.py check    # 5 个姿势测同一块，标定前散布基线
python3 raicom_handeye.py calib    # 标定：相机测量 + 正解真值 + 解平移 + 写 yaml
python3 raicom_handeye.py verify   # 残差 + 散布
python3 raicom_handeye.py reset    # 删 yaml 回厂方值
```

`calib` 只把臂抬到 `look_cargo` 拍一次，真值那边纯计算不动臂，不碰方块。
修正量超过 15 cm 会拒绝写文件（说明真值和测量不是同一块，或中途动了车）。

**标定前必须做到，否则真值不成立**：台面放一块 → `align` 对位 → 确认此时
`ready` + `close` 真能夹住 → 之后到标定结束车和方块都不要动。

`verify` 报两个数。残差是相机测的坐标和真值差多少，夹爪开口约 55 mm、方块 50 mm，
单边只剩 2.5 mm：≤5 mm 够抓，5~12 mm 勉强，>12 mm 夹不准。散布是 5 个观察姿势之间的
极差，用来区分「只是平移错」还是「旋转也错」——**标完平移散布还 >20 mm，说明旋转也不对，
那才需要完整 ArUco 手眼标定（8 姿势解 AX=XB）**。

## 5. 现在怎么抓

```bash
source ~/ros_ws/.typerc
source ~/ros_ws/devel/setup.bash
export ROS_MASTER_URI=http://127.0.0.1:11311    # 关键，见第 6 节
export ROS_IP=127.0.0.1
unset ROS_HOSTNAME
export OPENBLAS_CORETYPE=ARMV8

python3 ~/yolo_models/raicom_yolo_trt.py _show:=false &   # align 需要

# 手柄把车开到台前，方块在相机视野里就行，不用很准
python3 ~/yolo_models/raicom_grab_manual.py align   # 车自己横移/前后，对到 pick_aim
python3 ~/yolo_models/raicom_grab_manual.py ready
python3 ~/yolo_models/raicom_grab_manual.py close
```

实测 `align` 一次成功：目标 `nx=0.543 ny=0.076`，对位结果 `nx=0.503 ny=0.067`，
`ex=-0.041 ey=-0.006` 在容差内，对完自动重启手柄。

`align` 会先 `rosnode kill /joystick_control`（两个节点同时发 cmd_vel 会打架），
对完或超时都会 `roslaunch` 重启回来。

**对位完成后不要再动车**，一动固定姿势就失效。实测动过车之后 `close` 就夹空了。

`align` 失败只有一个常见原因：YOLO 看不到方块。日志里 `n=0 mode=detect` 就是这个。
先用手柄把车开到能看见的位置，`rostopic echo /raicom/target` 有数据再跑。

## 6. 踩过的坑

**`ROS_MASTER_URI` 必须手动设 `127.0.0.1`。** `.typerc` 把它设成车的 IP
`http://10.217.187.242:11311`，但 roscore 监听的是 localhost，不改就报
`Unable to register with master node`。

**不要 `rosnode kill /ros_robot_controller`。** 它一挂把 ROS master 也带走了，
`rosnode list` 直接空。恢复要全量重启：

```bash
killall -9 roslaunch rosmaster roscore
nohup roscore > /tmp/roscore.log 2>&1 &            sleep 5
nohup roslaunch hiwonder_bringup bringup.launch &  sleep 10
nohup roslaunch hiwonder_peripherals joystick_control.launch &
```

**手柄是 PS2 无线，走 STM32 板串口，不是 USB 也不是蓝牙。**
`/dev/input/js*` 是空的属于正常，`lsusb` 里没有手柄，`hcitool con` 也没有连接。
手柄失灵时 `/ros_robot_controller/joy` 零消息、`/dev/ttyUSB0` 无数据，
**重启软件节点没用**，要查手柄电源和物理配对（关手柄 → 拔插接收器 → 开手柄 → 按 MODE）。
配对好之后不用重启任何节点，`ros_robot_controller` 自己开始发 joy，实测 20 Hz。

**`raicom_arm.py` 的命令行没有 `look_cargo`。** 姿势在 `DEFAULT_POSES` 里有，CLI 没暴露。
要摆过去得自己写脚本调 `Arm.go("look_cargo")`。

**电脑端 SSH 用 paramiko 要预建 socket。** 这台机器上 paramiko 的
`ssh.connect(host)` 会 `getaddrinfo failed`（即使 ping 通、端口 22 通）：

```python
sock = socket.create_connection(('10.217.187.242', 22), timeout=10)
t = paramiko.Transport(sock)
t.connect(username='hiwonder', password='hiwonder')
```

PowerShell 里别用 `&&`、`||`、`2>nul`，也别在 `-c` 里塞带引号的长 python。
把命令写成 `.py` 文件再跑。
