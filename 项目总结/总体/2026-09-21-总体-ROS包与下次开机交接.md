## 4. 下次开机严格顺序

1. 充足电后开机，等厂方自启完成；确认新的 Wi-Fi/IP，不能盲用旧 IP。
2. 运行 `~/start_raicom_auto.sh`。该脚本会停止厂方自启、结束旧 master，再通过 `roslaunch raicom raicom.launch` 启动全向双地图栈。
3. RViz 使用 2D Pose Estimate：点在车的实际位置，箭头沿真实通道方向。以激光贴合黑围栏为准，不以地图网格或旧路点为准。
4. 用手柄沿通道慢速移动 20–40 cm 再返回，帮助 AMCL 收敛；不要抱车、不要原地旋转。
5. 检查协方差。建议至少压到位置约 5 cm、朝向约 2–3°量级后再存点；若仍为十几厘米或 7°以上，继续定位，不存点。
6. 调用一次：

   ```bash
   rosservice call /raicom/look_cargo
   rosservice call /raicom/status
   ```

   现场确认新姿势仍能看到顶面贴纸，并确认服务没有反馈误差。
7. 手柄停在安全观察位后，重新保存：

   ```bash
   rostopic pub -1 /raicom/save_pose std_msgs/String "data: pick"
   ```

8. **不要立刻试抓。** 新相机姿态必须重新标 `pick_aim`：先把底盘人工对到已知可抓的低层物理位置，YOLO 稳定看到目标后再执行 `raicom_arm.py save_aim`。仅仅“画面能看见”不能保存 aim。
9. 新 `pick` 和新 `pick_aim` 都确认后，才单跑一次 `test_pick`。观察机械臂实际动作，并用 `/raicom/status` 区分“动作完成”和“货物确实夹住”。
10. 单抓成功后才测试 `park1_approach/park2_approach → creep → place_low`；完整自动和高层抓放继续禁止。

## 5. 本轮发现并修正的问题

- 临时 SSH 脚本过多，固定流程已收进 `raicom` ROS 包和 launch。
- 原 `test_pick` 容易把“线程启动/命令发出”误写成成功，现已增加状态和舵机到位反馈。
- 原 `already_at` 只判断距离，车头方向错误也会跳过导航；现增加 20°朝向检查。
- 调试 Python3 验证进程曾异常退出码 132，但 RAICOM 节点、舵机管理器和反馈链路保持正常；后续改用 ROS 服务和舵机反馈完成单动作验证。
- `tools/04_vision_car/` 与 ROS 包里仍各有一份脚本。当前部署运行以 `ROS1/ros_ws-main/ros_ws/src/raicom/` 为准，姿势/路点运行数据以车上 `~/yolo_models/*.yaml` 为准；修改后必须同步备份，避免版本漂移。
