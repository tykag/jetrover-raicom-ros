---

## ⚠ 踩坑必记：Unable to communicate with master

**以后每个新终端都按「先查谁在跑 master，再对地址」做，不要盲设。**

### 错在哪

| 错误操作 | 结果 |
|----------|------|
| 终端 banner 里是 `192.168.10.110`，却强行 `export ...127.0.0.1` | 自启 master 若在局域网 IP 上 → **Unable to communicate** |
| 自启已在跑，又手动 `roscore` | **another roscore is already running** |
| 刚 `systemctl stop` 掉自启，却还用 127.0.0.1 去 `rostopic list` | master 已死 → **Unable to communicate** |
| 不看 `systemctl status` 就猜 | 地址对了但服务已崩溃循环 |

### 正确顺序（每次开新终端）

```bash
# 1) 自启在不在？
sudo systemctl status start_app_node.service --no-pager | head -20

# 2) 11311 被谁占着？
ss -ltnp | grep 11311

# 3) 再选地址，二选一试通即可：
source ~/ros_ws/devel/setup.zsh
unset ROS_HOSTNAME

# 试 A：本机（自启 source_env.bash 常用 localhost）
export ROS_MASTER_URI=http://127.0.0.1:11311
export ROS_IP=127.0.0.1
rostopic list

# 若报 Unable to communicate，再试 B：车载 WiFi IP
export ROS_IP=$(hostname -I | awk '{print $1}')
export ROS_MASTER_URI=http://${ROS_IP}:11311
echo "try $ROS_MASTER_URI"
rostopic list
```

- **A 或 B 通了**：这个终端后面全部用同一套，不要混。  
- **两个都不通**：没有可用 master → 先 `sudo systemctl start start_app_node.service` 等 40s，或手开 `roscore`。  
- **已有 master 时禁止再 `roscore`**。

自启脚本实际是：`ROS_IP=127.0.0.1` 且 `unset ROS_HOSTNAME`（见 `source_env.bash`）。新终端请用同一套；shell 默认 `.hiwonderrc` 常写成当前 WiFi IP，**两者混用就会踩坑。**

## 0. 核心原则

| 场景 | 网络 | ROS 地址怎么定 |
|------|------|----------------|
| 实验室 | 可能固定 `192.168.10.110` | 可用固定，或同样用「自动取 IP」 |
| **比赛外地** | **手机热点，IP 每次可能不同** | **必须开机自动读当前 IP** |

**推荐：实验室和比赛都用「自动检测本机 IP」**，只维护一套流程。

```text
ROS_IP          = 小车当前热点/WiFi 上的 IP（自动获取）
ROS_MASTER_URI  = http://$ROS_IP:11311
```

自启 bringup、视觉脚本、笔记本遥控，**都认这一套**。

## 1. 小车端：每次开机后怎么做

### 1.1 开机

1. 小车通电  
2. 手机开热点，小车连上热点（或实验室 WiFi）  
3. 等 **约 1 分钟** 让自启起来  

### 1.2 看自启是否在跑

```bash
sudo systemctl status start_app_node.service
```

应是 `active (running)`。否则：

```bash
sudo systemctl restart start_app_node.service
```

### 1.3 用「当前 IP」进 ROS（不要手写死实验室 IP）

```bash
source ~/ros_ws/devel/setup.zsh

# 自动取第一个 IPv4（热点下就是当前地址）
export ROS_IP=$(hostname -I | awk '{print $1}')
export ROS_MASTER_URI=http://${ROS_IP}:11311
unset ROS_HOSTNAME

echo "本机 IP: $ROS_IP"
echo "MASTER:  $ROS_MASTER_URI"

rostopic list
rostopic hz /depth_cam/rgb/image_raw
```

能 `list`、有相机帧率 → 正常。

### 1.4 跑视觉

```bash
python3 ~/yolo_models/raicom_yolo_trt.py
```

或一键（见下文脚本）：

```bash
~/start_raicom_vision.sh
```

## 2. 电脑端（遥控 / WinSCP / 看话题）

比赛时笔记本也连**同一个手机热点**。

1. 在小车上执行 `hostname -I`，看清车的 IP（例如 `192.168.43.XX`）  
2. 在电脑上看自己的 IP（Windows：`ipconfig`）  
3. 电脑终端 / 远程环境设置：

```text
ROS_MASTER_URI = http://<小车IP>:11311
ROS_IP         = <电脑自己的IP>
```

WinSCP / MobaXterm 主机名填 **小车当前 IP**（每次热点重连后可能要改）。

## 3. 自启为什么有时仍是旧 IP？

若 `start_app_node` 启动时写死了 `192.168.10.110`，换热点后自启里的 master 会和真实 IP 不一致。

**比赛前务必改成：自启用包装脚本，启动时自动取 IP**（见 `tools/01_startup/ros_env_auto.sh` + 服务改法说明）。

临时应急（比赛现场）：

```bash
sudo systemctl stop start_app_node.service
# 用自动 IP 手开 bringup（见一键脚本里的手动模式）
```

长期：改自启，让每次开机都 `export ROS_IP=$(hostname -I | awk '{print $1}')` 再 `roslaunch`。

## 4. 一键脚本（小车）

文件：`~/start_raicom_vision.sh`（由 `tools/01_startup/start_raicom_vision.sh` 拷贝）

作用：

1. 自动设置 `ROS_IP` / `ROS_MASTER_URI`  
2. 等待 `rostopic list` 成功  
3. 启动 `raicom_yolo_trt.py`

```bash
chmod +x ~/start_raicom_vision.sh
~/start_raicom_vision.sh
```

## 5. 比赛当天流程（简版）

```text
□ 手机开热点（建议热点名称/密码固定，小车设为自动连接）
□ 小车开机，确认已连上热点
□ 等自启 ~1 分钟；status → active
□ 小车：hostname -I 记下 IP；跑 ~/start_raicom_vision.sh
□ 电脑：连同一热点；WinSCP/ROS 填小车当前 IP
□ 视觉 TRT running；正对分拣板出现 MAPPING LOCKED
□ 再进全自动导航/抓取（后续节点同样 source 自动 IP 脚本）
```
